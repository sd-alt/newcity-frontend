# 传感器完整档案交互说明

资源中心现有导航保持不变。用户可以从传感器资源列表、观测能力管理或地图抽屉进入传感器完整档案，入口最多两次点击即可到达目标分区。

## 入口与返回

资源列表提供查看、编辑基础信息、维护完整档案、地图定位和更多操作；传感器名称进入只读档案。观测能力管理提供编辑观测能力、维护完整档案和地图定位。地图抽屉中的对象是观测平台，点击档案操作后先查询该平台下的传感器：单传感器直接进入，多传感器显示紧凑选择列表，不能把平台 ID 当作传感器 ID。若接口返回空关联，页面不再停留在“没有可维护档案”的死路，而是自动打开“新增传感器”步骤，并预填所属平台和档案名称；这类新档案仍需维护人员补充真实资料后才能用于任务匹配。

入口通过 `/resources/sensors` 的 `sensorId`、`section`、`mode` 查询参数定位。来自 Agent 任务的 `runId`、`returnTo`、`currentTab` 会继续透传，返回任务页面时不丢失业务上下文。

## 编辑体验

- 每个分区拥有独立草稿；切换分区前会提示未保存修改。
- 保存成功后重新读取后端数据，页面显示的是服务端回显。
- `mode=view` 切换八个分区后继续保持只读；有权限的用户通过“进入编辑”显式切换，退出编辑也会处理未保存草稿。
- 未保存保护覆盖当前分区、量测项、接口、履历、重访周期和高级 JSON；切换分区、返回来源页、浏览器路由离开和刷新都会提示。
- 量测项和接入接口使用表格维护，删除需要确认，保存时一次性提交。
- 接口只接受 `env:`、`secret:`、`vault:` 引用；后端只回显“已配置”，编辑时留空保持原引用，不把占位文案重新保存成真实值。

## 业务中心阶段顺序

业务中心保留原路由和 Tab，二级导航不展示阶段编号，统一按以下顺序显示：

```text
需求查询
资源选择
能力评估
资源配置
方案管理
过程管理与成果追溯
```

跨阶段保留 `taskId`，已有时继续保留 `planId`、`runId`、`demandId`、`returnTo` 和 `currentTab`。需求查询页作为统一任务入口；过程追溯页显示当前任务、阶段、方案和运行上下文。

## 与任务匹配的边界

档案完整度只用于告诉用户哪些元数据已经维护。任务候选筛选仍由后端的传感器任务匹配服务判断空间、时间、分辨率、精度、覆盖率、权限和调度占用，不能用档案完整度替代任务匹配结果。
