# Agent任务工作台交互说明

## 创建态与运行态

没有运行记录时页面只显示场景、自然语言需求、任务方式和启动按钮。明确的时间、区域、更新频次等约束收纳在“添加明确约束”中，需求输入默认为空，示例通过点击填入。

有运行记录时页面切换为运行态，不再重复显示创建表单。顶部只保留任务运行标识和“新建任务”，其下依次为“当前需要处理”面板和四个内容页签：

- 概览：当前动作、业务状态、识别需求、人工输入和风险；
- 任务图：规划四节点和默认简化业务图；
- 结果：最终业务摘要和阶段成果；
- 技术记录：完整节点代码、执行方式、Checkpoint、模型调用、工具调用和工件审计。

当前动作面板始终只提供一个主按钮，其他恢复、接管、取消和刷新动作进入“更多”。需求补充、指标确认、方案确认、下发确认、执行异常和 Checkpoint 故障均从这一处进入。

## 业务化展示规则

默认页面不展示 Executor、nodeType、Checkpoint 编号、模型 Token 等内部字段。任务图默认显示步骤名称、状态和依赖；需要排查问题时进入“技术记录”查看完整数据。最终结果同时兼容顶层摘要和 `result.summary`/`result.reply`。

方案资源选择中的期望版本为只读的当前版本，避免用户提交过期版本。复杂的指标或业务方案调整会带上任务、方案、运行和版本上下文返回业务中心，完成后可回到原 Agent 任务。

## 响应式规则

工作区限制横向溢出；中等屏幕将任务图调整为两列，小屏幕调整为单列，创建方式和当前动作面板在小屏幕纵向排列。主要业务信息和技术记录字号不低于 11px。

回滚方式：执行 `git revert <本轮前端提交>`；不涉及业务数据库删除。
