# Agent任务工作台交互说明

## 创建态与运行态

没有运行记录时页面只显示场景、自然语言需求、任务方式和启动按钮。明确的时间、区域、更新频次等约束收纳在“添加明确约束”中，需求输入默认为空，示例通过点击填入。

有运行记录时页面切换为运行态，不再重复显示创建表单。顶部只保留任务运行标识和“新建任务”，其下依次为“当前需要处理”面板和四个内容页签：

- 概览：当前动作、业务状态、识别需求、人工输入和风险；
- 任务图：规划四节点和默认简化业务图；
- 结果：最终业务摘要和阶段成果；
- 技术记录：完整节点代码、执行方式、Checkpoint、模型调用、工具调用和工件审计。

当前动作面板始终只提供一个主按钮，其他恢复、接管、取消和刷新动作进入“更多”。需求补充、指标确认、方案确认、下发确认、执行异常和 Checkpoint 故障均从这一处进入。

当前动作按运行状态收口：人工执行显示“填写人工结果”，人工完成提交后显示“正在恢复自动执行”；不可重试失败显示“人工接管”，执行异常只进入结构化异常处置，需求补充不再显示普通“确认并继续”。所有审批、补充、执行处置、资源替换和刷新操作共享 `activeActionKey`，提交期间按钮禁用并显示提交中，避免一次点击产生两条调用链。

## 业务化展示规则

默认页面不展示 Executor、nodeType、Checkpoint 编号、模型 Token 等内部字段。任务图默认显示步骤名称、状态和依赖；需要排查问题时进入“技术记录”查看完整数据。最终结果同时兼容顶层摘要和 `result.summary`/`result.reply`。

方案资源选择中的期望版本为只读的当前版本，避免用户提交过期版本。候选列表展示资源类型、感知要素、覆盖率、时间分辨率、可靠性和匹配原因，不自动选中旧资源或第一个候选；不可用候选折叠展示，没有可用候选时不能提交。复杂的指标或业务方案调整会带上任务、方案、运行和版本上下文返回业务中心，完成后可回到原 Agent 任务。

从任务图、结果或技术记录页点击当前动作后，工作台先切回概览，再定位并聚焦对应人工表单：需求补充、普通审批、方案资源选择、执行异常和人工执行分别使用独立容器，不复用模糊的最后一个审批面板。方案评价摘要在概览、方案确认和结果页复用同一数据，展示总分、要素满足度、共同覆盖率及要求、时效、利用率、成本、风险、策略版本和阻断原因；`approvalAllowed=false` 时确认按钮禁用。

## 响应式规则

工作区限制横向溢出；宽屏打开地图详情时保留 Agent 左侧区形成三列，中等屏幕详情抽屉覆盖地图但不销毁 Agent 区，小屏幕抽屉覆盖后关闭可恢复原状态。抽屉以地图对象快速查看为主，复杂编辑通过业务中心跳转并携带任务、运行、方案、版本和返回页签。中等屏幕将任务图调整为两列，小屏幕调整为单列，创建方式和当前动作面板在小屏幕纵向排列。主要业务信息和技术记录字号不低于 11px。

回滚方式：执行 `git revert <本轮前端提交>`；不涉及业务数据库删除。
